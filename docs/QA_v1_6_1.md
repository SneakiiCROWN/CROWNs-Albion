# v1.6.1 dialog audit and QA — 17 October 2026

## Reproduction and cause

Launched the v1.6 CROWNsAlbion.exe directly on the user's Windows desktop, with Fable III not running. Clicked EXACT AMOUNT. Accessibility inspection found the amount dialog still alive and the main HWND disabled; native captures showed the child obscured by the main menu. This was a hidden modal session, not a failed cheat. The old regression used a hidden main form and did not test this z-order/activation state.

The main window was TopMost while custom dialogs were in the normal window band. RegisterPad forced child HWND creation before ShowDialog assigned ownership. Other popups used ownerless MessageBox/file-dialog calls. Keyboard preprocessing could also invoke the owner's focused Quick Gold button while a modal was active, producing duplicate amount windows.

## Shared repair

- Main and child windows use the same normal z-order band; removed forced TopMost. Explicit ownership is set before child handle creation. RegisterPad binds on HandleCreated and removes routes on destruction/close.
- All custom dialogs go through ShowPopup: nearest active dialog owns nested children, CenterParent positioning, one modal stack, deterministic disposal and conditional focus restoration. Library now uses this same modal lifecycle and includes Back/Close.
- Replaced every unowned message box with an owned PopupForm notice/confirmation. OK, Yes/No, error, help and warnings share Escape/B and A/Enter handling. No game-related confirmation is bypassed.
- Open/save/folder pickers all use ShowCommon with an explicit owner. Native coordinates avoid mixing cached WinForms coordinates with shell DPI contexts. A short 750ms positioning stabilization prevents shell startup placement from overwriting the centred location; it stops repositioning afterward.
- Modal keys are intercepted before WinForms can activate a button on a disabled owner. Reopening an already active amount/queue/library window raises the current dialog instead of nesting duplicates.
- Hold B and F8 cancellation unwind nested dialogs, let Windows re-enable each owner, then hide the main menu. The parent is never forcibly enabled during a modal session. F8/tray can reopen the menu with no game running. Focus returns to the current owner after cancel/confirm, without stealing it from another app.

- **37 controller/native-window checks passed**, including simulated held-button transitions and shared native confirmation callbacks. The inherited harness now also shows its owner and accounts for the modal library.
- **15 Python regressions passed**; package and reference checks pass.
- Separately launched the standalone CROWNsAlbion.exe and used native computer-use to click EXACT AMOUNT; verified it stayed visible/centred after settling, Escape returned to the main menu, Ctrl+G/Enter confirmed without a duplicate dialog, Ctrl+Q/Escape recovered, and Library/Escape recovered.
